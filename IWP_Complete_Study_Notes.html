UNIT 1

Introduction to Internet & Web Architecture

5 hrs

What is the Internet, and what is the Web?

The Internet is a global network of interconnected computers that communicate using a common set of rules (protocols like TCP/IP). The World Wide Web (WWW) is one service that runs on top of the Internet — a system of linked documents (webpages) accessed via HTTP/HTTPS. Email, FTP, and video calls also run on the Internet but are not "the Web".

Why this distinction matters: exam questions like "differentiate between web browser and web server" are really testing whether you understand that the Web is a client–server system running over the Internet, not the Internet itself.

Client–Server Architecture

Every website interaction follows a request–response cycle:

TermWhat it isExample
Client / Web BrowserSoftware that requests a page and renders (displays) the HTML/CSS/JS it receives.Chrome, Firefox, Edge
Web ServerA machine/program that stores website files and responds to requests by sending them back.Apache, Nginx, IIS
HTTP/HTTPSThe protocol (rules) used for the request–response conversation. HTTPS = HTTP + encryption.https://example.com
URLThe address that identifies a resource on the web.https://www.college.edu/about.html
DNSTranslates human-readable domain names into IP addresses.google.com → 142.250.xx.xx
Why it matters: the browser never runs your JavaScript on the server — it downloads HTML/CSS/JS and executes them locally. That's why we call this course "client-side" web programming — everything you write (HTML/CSS/JS/jQuery) executes inside the user's browser, not on the server.

Static vs Dynamic Websites

  • Static website: same content for every visitor; pure HTML/CSS (and maybe JS for interactivity). No database.
  • Dynamic website: content changes based on user, time, or database (needs a server-side language like PHP/Node/Python + database). JavaScript can make a static page feel dynamic (DOM updates) but that's still client-side.

Planning a Website

Before writing code, a real project goes through:

  1. Purpose & audience — what problem does the site solve, for whom?
  2. Site map / information architecture — list of pages and how they link together (Home → About → Courses → Contact).
  3. Wireframe — rough sketch of layout (header, nav, main content, footer) before styling.
  4. Content gathering — text, images.
  5. Build → Test → Publish (host) → Maintain.
Why this matters for exams: Q1(b)-type questions ("design a webpage with a list") are really asking you to translate a small plan into working markup — always mentally sketch structure before typing tags.
UNIT 2

HTML — Structure & Text Formatting

12 hrs

What HTML actually is

HTML (HyperText Markup Language) is not a programming language — it has no logic, loops, or variables. It is a markup language: you wrap content in tags to tell the browser what that content means (a heading, a paragraph, a list) so the browser knows how to render and structure it.

Why tags come in pairs: most tags have an opening <tag> and closing </tag> so the browser knows exactly where an element's content starts and ends — this lets elements nest inside each other, which is how complex layouts are built from simple pieces.

The Skeleton of Every HTML Document

<!DOCTYPE html>          <!-- tells browser: use modern HTML5 rules -->
<html>
  <head>
    <title>Page Title</title>   <!-- shows in browser tab, not on page -->
  </head>
  <body>
    <!-- everything visible on the page goes here -->
  </body>
</html>
Output
Browser tab: Page Title
(empty page body — nothing added yet)
Why <head> vs <body>: <head> holds metadata (title, CSS links, character encoding) — information about the page. <body> holds everything the user actually sees. Mixing them up is a very common beginner mistake.

Text Formatting Tags

TagPurpose
<b>Bold text — visual only, no semantic meaning
<strong>Bold text that is also semantically "important" (screen readers emphasize it)
<i>Italic — visual only
<em>Italic + semantic "emphasis"
<u>Underline
<h1>…<h6>Headings, h1 = most important/largest, h6 = least
<p>Paragraph (block of text, browser adds space before/after)
<br>Single line break (no closing tag — it's an "empty" element)
<hr>Horizontal rule — a divider line
<marquee>Scrolling text (obsolete, but syllabus/exam still references it)
Exam-important: <b> vs <strong> and <i> vs <em> is a classic "differentiate" question. The answer is always: identical default appearance, but the second one of each pair carries semantic meaning (matters for SEO and accessibility/screen readers).

</p>

Why this exact syntax matters: this is literally 2026 paper Q1(a) — font size, font family, font colour must be set with a single style attribute containing CSS property:value pairs separated by semicolons.

Links & Images

Hyperlinks — <a>

<a href="https://college.edu" target="_blank">Visit College</a>
Output
Visit College
Clicking it opens college.edu in a brand-new browser tab (because of target="_blank").
AttributePurpose
hrefDestination URL (external site, another page, or #id for same-page jump)

Internal vs External linking: External = href points to another website (https://...). Internal = href points to another page/section of the same site, e.g. href="contact.html" (another file) or href="#section2" (jumps to an element with id="section2" on the same page).

Images — <img>

</a>

A small clickable icon — clicking it navigates to facebook.com, exactly like a text link would.

The <div> Element & Semantic Layout Tags

Why <div> exists: it is a generic, invisible "box" with no meaning of its own — used purely to group other elements so you can style or position them together as one unit (e.g. a whole navigation bar, a card, a section).
<div id="top">My Webpage</div>
<div id="bottom">
  <div id="left">Table of contents</div>
  <div id="right">Main Content</div>
</div>
Output
My Webpage
Table of contents
Main Content
Every <div> is a block element, so — with no CSS applied yet — each one simply stacks on its own line, full width.
Exam pattern (2026 Q5a): "divide the browser window into two horizontal sections, bottom split into left/right" — this is solved purely with nested <div>s + CSS (display:flex or floats) — full solution is in the Solved Paper section below.

Tables

Why tables exist: for displaying genuinely tabular/grid data (timetables, price lists) — rows and columns with real relationships between cells. (Never use tables just for page layout — that's what CSS/divs are for.)
<table border="1">
  <tr>                         <!-- table row -->
    <th>Day</th>            <!-- table header cell (bold, centered) -->
    <th>Period 1</th>
  </tr>
  <tr>
    <td>Monday</td>       <!-- table data cell -->
    <td>Math</td>
  </tr>
</table>
Output
DayPeriod 1
MondayMath

rowspan and colspan

What problem they solve: normally every row needs the same number of <td> cells to line up in a grid. When one label logically applies to multiple rows or columns (e.g. "Monday" applies to 2 rows of periods), you merge cells instead of repeating the label.
AttributeMeaning
rowspan="2"This cell stretches down and occupies 2 rows (vertically merges)
colspan="2"This cell stretches across and occupies 2 columns (horizontally merges)

Rule: when a cell uses rowspan/colspan, the rows below/beside it must have one fewer <td> to keep column count balanced.

<table border="1">
  <tr>
    <th>Day</th><th>Period 1</th><th>Period 2</th><th>Period 3</th>
  </tr>
  <tr>
    <td rowspan="2">Monday</td>
    <td>Math</td><td>English</td><td>Science</td>
  </tr>
  <tr>
    <td colspan="2">History and Art</td><td>Music</td>
  </tr>
</table>
Output
DayPeriod 1Period 2Period 3
MondayMathEnglishScience
History and ArtMusic
Notice "Monday" visually spans both rows, and "History and Art" visually spans two columns.

↑ Note row 2 only has 3 <td>s because Monday (rowspan=2) already fills the first column. Row 3 only has 2 <td>s because colspan=2 covers 2 columns in one cell.

Images/background inside tables + CSS colours

<td><img src="icon.png" alt="icon"></td>   <!-- image as cell data -->

/* in CSS */
table { background-color: lightyellow; }
td { color: darkblue; }
Output
🖼️ icon
The whole table gets a light-yellow background; text inside cells turns dark blue.

Web Forms

Why forms exist: they are the mechanism for collecting user input — every login page, search bar, and registration page is built from <form> and input controls. This is also the bridge to JavaScript, since JS is what reacts to and validates that input.
<form>

  <!-- a. Text Box -->
  <label>Name:</label>
  <input type="text" id="name" name="name"><br><br>

  <!-- b. Text Area (multi-line input) -->
  <label>Address:</label>
  <textarea rows="3" cols="30"></textarea><br><br>

  <!-- c. Dropdown box -->
  <label>Course:</label>
  <select>
    <option>BSc CS</option>
    <option>BCA</option>
  </select><br><br>

  <!-- d. Option/radio buttons (only ONE can be picked — same 'name') -->
  <input type="radio" name="gender" value="M">Male
  <input type="radio" name="gender" value="F">Female<br><br>

  <!-- e. Check boxes (MULTIPLE can be picked) -->
  <input type="checkbox" name="hobby" value="music">Music
  <input type="checkbox" name="hobby" value="sports">Sports<br><br>

  <!-- f. Reset and Submit buttons -->
  <input type="submit" value="Submit" onclick="alert('Form submitted'); return false;">
  <input type="reset" value="Reset">

</form>
Output
Name:

Address:


Course:

Male   Female

Music   Sports

Clicking Submit runs the alert "Form submitted" and — because onclick returns false — the page does NOT actually reload/navigate.

Why every input needs a "name" attribute

The name attribute is what gets sent to a server / read by JavaScript as the key for that field's value. id is used for labels/CSS/JS-DOM targeting — id and name serve different jobs and a form control commonly needs both. Radio buttons in the same group MUST share the same name so the browser knows only one of them can be selected at a time.

Frames (older technique, still in syllabus)

What frames do: split the browser window into independently-scrollable sub-windows, each loading a different HTML file. Mostly replaced today by CSS layout + <iframe>, but the concept ("top frame = logo, left frame = nav links, right frame = content") is a classic syllabus question.
<!-- frameset.html -->
<frameset rows="20%,80%">
  <frame src="header.html">
  <frameset cols="20%,80%">
    <frame src="nav.html">
    <frame src="content.html" name="main">
  </frameset>
</frameset>
Output
The browser window splits into 3 fixed panes: a thin strip across the top (20% height) showing header.html, and the remaining 80% split again into a narrow left pane (nav.html) and a wide right pane (content.html) — each pane scrolls independently and loads its own file.

Modern equivalent: <div> + CSS display:flex/grid (used in the Solved Paper Q5a below), since <frameset> is deprecated in HTML5.

UNIT 3

CSS — Cascading Style Sheets

8 hrs

What CSS is and why it's separate from HTML

HTML says what content is (a heading, a paragraph). CSS says how it looks — colour, size, spacing, layout. Keeping them separate means you can completely re-skin a site by changing one CSS file, without touching a single HTML tag.

The Three Types of CSS

Why three types exist: each solves a different scope problem — style one element only, style one page, or style an entire multi-page site consistently.
TypeWhere it livesScopeReusability
Inline CSSstyle="..." attribute on the tag itselfThat single element onlyNone — must repeat on every element
Internal CSS<style> block inside <head>Whole current pageNot shared across pages
External CSSSeparate .css file, linked with <link>Every page that links itBest — one file styles the whole site, cached by browser
<!-- 1. Inline -->
<p style="color:blue;">Hello</p>

<!-- 2. Internal -->
<head>
  <style>
    p { color: blue; }
  </style>
</head>

<!-- 3. External -->
<head>
  <link rel="stylesheet" href="style.css">
</head>

/* style.css */
p { color: blue; }
Output

Hello

Hello

Hello

All 3 methods (inline / internal / external) produce the exact same visual result — blue "Hello" text — proving the technique used doesn't change what the browser shows, only how reusable/maintainable the CSS is.
Priority ("cascade") rule when styles conflict: Inline > Internal/External (whichever comes later in the <head> wins if both target the same element) > Browser default. This ordering is literally called the "Cascade" in "Cascading Style Sheets".

CSS Selectors

What a selector does: it's the "address" that tells the browser which elements a rule applies to.
SelectorSyntaxMatches
Element/typep { }Every <p> on the page
Class.text { }Every element with class="text" (reusable, many elements)
ID#id1 { }The one element with id="id1" (unique)
Universal* { }Every element
Descendantdiv p { }<p> elements that are inside a <div>
Pseudo-classa:hover { }An element in a particular state (mouse hovering)
Worked example (2026 paper Q1d) 3 marks
<style>
  p{ color: blue; }
  .text { color: green; }
  #id1 { color: red; }
</style>
...
<p id="id1" class="text">Sample Text</p>
Output

Sample Text

Even though the element-selector rule (blue) and the class rule (green) both match this <p>, the id rule (red) wins because id selectors have the highest specificity of the three.

Answer: Final colour = red.

Why: ID selectors have higher specificity (a stronger, more specific match) than class selectors, which in turn beat element/type selectors. Specificity ranking, weakest to strongest: element < class < id < inline style. It is not about which rule is written last — #id1 wins over .text regardless of order because ID is inherently more specific.

id selector vs class selector — the direct comparison (exam favourite)

id selector (#)class selector (.)
Can be reused?No — one id per pageYes — many elements, many times

Typical use caseStyle/target one unique block (a specific header)Style a repeated pattern (all buttons, all cards)

The CSS Box Model

Why it exists: every single HTML element the browser renders is treated as a rectangular box. The box model defines the 4 layers of that box from the inside out — understanding it is essential for controlling spacing and size precisely.
LayerWhat it isEffect on total element size
ContentThe actual text/image — controlled by width/heightBase size
PaddingTransparent space inside the border, between border and contentIncreases the box's visible size; background colour extends into padding
BorderA visible line wrapping the padding+contentAdds its own thickness to total size
MarginTransparent space outside the border, between this box and neighbouring elementsDoes NOT add to the element's own size — only pushes other elements away; margin is always transparent (no background)
.card {
  width: 200px;
  padding: 16px;      /* inside spacing, pushes content inward */
  border: 2px solid black;
  margin: 10px;       /* outside spacing, pushes other elements away */
}
Output
200px content box
(padding = light-blue area, border = black line, margin = the invisible gap you'd see around this box next to other elements)
Key distinction (2026 paper Q4d "differentiate margin and padding"): Padding is inside the border and shares the element's own background colour. Margin is outside the border, is always transparent, and is used to create space between separate elements rather than inside one.

Individual sides: margin-top, margin-right, margin-bottom, margin-left (same pattern for padding and border). Shorthand margin: 10px 5px 10px 5px; goes clockwise from top: top, right, bottom, left.

Block vs Inline Elements & Page Layout

Why this distinction matters: it determines how an element takes up space and whether it can sit next to other elements — critical for layout debugging.
Block elementsInline elements
WidthTake up the full width available, always start on a new lineTake up only as much width as their content needs
width/height CSSRespectedIgnored (mostly)
Examples<div>, <p>, <h1>, <ul>, <table>, <section><span>, <a>, <b>, <img>, <input>
Practical rule: use block elements as structural containers/sections; use inline elements for small runs of text or controls that must sit within a line of text (e.g. bolding one word mid-sentence with <strong>).

CSS for Structural Layout — display:flex (modern webpage layout)

Why flexbox: before flex/grid, developers hacked layouts with floats. Flexbox gives a clean, predictable way to arrange child elements in a row or column, distribute space, and align items.
#bottom {
  display: flex;          /* lays children out side-by-side (row) */
}
#left  { width: 30%; }
#right { width: 70%; }
Output
left (30%)
right (70%)
#left and #right now sit side-by-side in one row instead of stacking vertically.

Dropdown Navigation Menu (CSS-only)

How a pure-CSS dropdown works: the submenu is hidden by default (display:none) and only shown when the user hovers the parent — no JavaScript required.
<ul class="menu">
  <li>Faculty
    <ul class="submenu">
      <li>Prof. A</li>
      <li>Prof. B</li>
    </ul>
  </li>
</ul>

/* CSS */
.menu { list-style: none; }
.submenu { display: none; position: absolute; }
.menu li:hover .submenu { display: block; }  /* show on hover */
Output
Faculty ▾
Prof. A
Prof. B
In the real page the submenu (Prof. A / Prof. B) is hidden until the mouse hovers "Faculty" — shown here open so you can see what it looks like.
UNIT 4

JavaScript

10 hrs

What JavaScript is and why it exists

HTML = structure. CSS = appearance. JavaScript (JS) = behaviour/logic. It's a real programming language (variables, conditions, loops, functions) that runs inside the browser and can change the page after it has loaded — react to clicks, validate a form before submission, fetch data, animate things — without reloading the page.

Why JS is the most important unit here: HTML/CSS are static once loaded. JS is what makes a page interactive — almost every "real" feature (validation, calculators, dynamic content) needs it.

Where JavaScript code goes

<!-- 1. Inside <script> tags in the HTML file -->
<script>
  alert("Hello");
</script>

<!-- 2. External file (best practice, cacheable, reusable) -->
<script src="script.js"></script>
Output
Method 1: a popup dialog box appears immediately when the page loads, showing the text "Hello". Method 2: nothing visible happens yet by itself — script.js only defines/runs code once the browser fetches and executes that external file.
Placement tip: put <script> just before </body> (or use the defer attribute) so the HTML has fully loaded before your JS tries to find/manipulate elements — otherwise document.getElementById() may not find an element that hasn't been parsed yet.

Output methods — how JS shows information

MethodWhat it does
document.write()Writes directly into the HTML page (only works before page fully loads — mostly for teaching/demo)
alert()Shows a popup dialog box with a message
console.log()Prints to the browser's developer console (for debugging, not seen by users)
innerHTMLSets/reads the HTML content inside an element — the standard way to update visible page content dynamically
prompt()Popup box that asks the user for input and returns what they typed (always as a string!)

Variables & Data Types

Why variables exist: a variable is a named container that stores a value in memory so you can reuse/change it later instead of retyping literal values everywhere.
KeywordMeaning
varOld-style declaration — function-scoped, can be re-declared (syllabus/older textbooks use this)

constBlock-scoped, value cannot be reassigned after creation
var a = 5;        // number

const isPass = true; // boolean
Output
(no visible output — these lines just create 3 variables in memory: a=5, name="Riya", isPass=true. Nothing is printed until you explicitly call document.write(), alert(), or console.log() on them.)

Arrays in JavaScript (2026 paper Q1f)

What an array is: a single variable that holds an ordered collection of values, each accessible by a numeric index starting at 0.
let fruits = ["Apple", "Banana", "Mango", "Orange", "Grapes"];
console.log(fruits[2]);  // "Mango" — index 2 = 3rd item (index starts at 0!)
Output
Mango (printed to the browser's Developer Console — press F12 to see it. Array indexes start at 0, so index 2 is the 3rd element: Apple(0), Banana(1), Mango(2).)

Worked example — string concatenation vs numeric addition (2026 paper Q6b) 3+2+2 marks

The + operator does numeric addition only if both operands are numbers. If either side is a string, + switches to concatenation (joining text) instead.

var a = 5;
var b = 2;
document.write(a + b);        // → 7        (number + number = arithmetic)
document.write(a + "2");      // → "52"      (number + string = concatenation, NOT 7)
document.write(a - "2");      // → 3        (- has no "text join" meaning, so JS converts "2" to number 2)
Output
7 52 3

Why the difference: + is overloaded (does two different jobs based on operand types), but -, *, / only mean subtraction/multiplication/division — so JS always tries to convert strings to numbers for those operators.

Worked example — == vs === (2026 paper Q6b(ii))
var x = 10;         // number
var y = "10";       // string
if (x == y) { ... }   // TRUE — == converts types before comparing, 10 == "10" → 10 == 10
if (x === y) { ... }  // FALSE — === also checks type: number !== string
Output
First if → TRUE → "Equal" branch runs Second if → FALSE → "Not Equal" branch runs (== converts "10" to the number 10 before comparing, so it matches. === refuses to convert, so a number can never strictly equal a string.)

Output of the paper's snippet: "Equal" — because it uses ==, which performs type coercion, so 10 == "10" evaluates to true.

Worked example — truthy/falsy empty string (2026 paper Q6b(iii))
var x = "";      // empty string

Compare & explain (2026 paper Q3) 9 marks

(i) onclick vs ondblclick — onclick fires after one single click; ondblclick fires only after two rapid clicks. Never use both to react to the "same" click — they can conflict since a double-click also triggers two single-click events first.

(ii) onmouseover vs onmouseout — onmouseover fires the instant the cursor enters the element's boundary; onmouseout fires the instant it leaves. They're typically used as a pair to create hover effects (e.g. highlight on enter, revert on exit) — exactly like Practical Q5 in your list.

(iii) onkeydown vs onkeyup — onkeydown fires the moment a key is physically pressed down (fires repeatedly if held); onkeyup fires once, only when the key is released. Use onkeydown for real-time reactions (like a game), onkeyup when you want the final typed value (like live search-as-you-type, checked after the key event completes).

Client-Side Form Validation

Why validate on the client (browser) side: catching bad input before it's submitted gives instant feedback to the user (no page reload/server round-trip needed) and reduces junk data reaching the server. This is the single most exam-heavy practical topic (Practical Q4, Q7).
function validateForm() {
  let roll = document.getElementById("roll").value;
  let name = document.getElementById("name").value;
  let dob  = document.getElementById("dob").value;

  // a. Roll number must be exactly 7 digits, numeric only
  if (!/^\d{7}$/.test(roll)) {
    alert("Roll number must be a 7-digit number");
    return false;   // stops the form from submitting
  }
  // b. Name must be alphabetic only
  if (!/^[A-Za-z\s]+$/.test(name)) {
    alert("Name must contain only letters");
    return false;
  }
  // c. DOB must not be empty
  if (dob === "") {
    alert("Date of birth is required");
    return false;
  }
  return true;   // all checks passed → allow submission
}
Output
Try submitting with roll="12A45", or name="John3", or an empty DOB field → each one pops an alert() with the matching error message and blocks the form from submitting (return false). Only when ALL three checks pass does the function return true and the form actually submits.
Why return false matters: when this function is wired to <form onsubmit="return validateForm()">, returning false tells the browser "cancel the submit", while true lets it proceed. This is the standard validation pattern.
Regex quick reference used above: ^=start, $=end, \d{7}=exactly 7 digits, [A-Za-z\s]+=one-or-more letters/spaces, ! before test() means "does NOT match".

JSON — JavaScript Object Notation

Why JSON exists: when a webpage needs to store structured data or send/receive it from a server, plain text isn't enough (no structure) and full JS objects can't easily travel across a network. JSON is a lightweight, text-based, language-independent format for representing structured data — it looks just like a JS object literal, which makes it trivial to use directly in JavaScript.

JSON syntax rules

Q2(b) CSS Box Model — components, and how padding/border/margin affect layout 8

The box model has four nested layers around every element: content (text/image, sized by width/height) → padding (inner cushion between content and border, shares the element's background) → border (visible edge, adds its own width to the box) → margin (outer transparent gap that separates this box from its neighbours, does not affect the box's own rendered size).

Effect on layout: increasing padding makes the visible box bigger without changing the width value itself (unless box-sizing:border-box is set). Increasing border width also visually enlarges the box. Increasing margin never changes the box's own size — it only pushes surrounding elements further away, which is why margins are used for spacing between elements while padding is used for spacing inside one element.

.card {
  width: 200px;
  padding: 20px;              /* space inside the border */
  border: 3px solid #333;
  margin: 15px;               /* space outside the border */
  background-color: lightyellow; /* fills content + padding, NOT margin */
}
Output
Card content
The light-yellow background fills the padding too (it's part of the box) but stops at the border — the 15px margin around it stays fully transparent.

Q4 — Differentiate: block vs inline, b vs strong, browser vs server, margin vs padding 8

Block vs inline: block elements always start on a new line and take full available width (<div>, <p>); inline elements flow within a line and only take the width of their content (<span>, <a>).

<b> vs <strong>: identical bold appearance by default, but <strong> carries semantic "importance" meaning (read differently by screen readers, better for SEO); <b> is purely visual.

Web browser vs web server: the browser is client software that requests and renders pages (Chrome, Firefox); the server is the machine/software that stores site files and responds to those requests (Apache, Nginx).

Margin vs padding: margin is transparent space outside an element's border (separates it from neighbours); padding is space inside the border (separates content from the border, shares the element's own background).

Q6(a) Complete HTML+JS calculator (add/sub/mul/div, Clear button) 9
<label>Number 1: </label><input type="number" id="num1"><br>
<label>Number 2: </label><input type="number" id="num2"><br>
<label>Operation: </label>
<select id="op">
  <option value="+">Addition (+)</option>
  <option value="-">Subtraction (-)</option>
  <option value="*">Multiplication (*)</option>
  <option value="/">Division (/)</option>
</select><br>
<button onclick="calculate()">Calculate</button>
<button onclick="clearAll()">Clear</button><br>
<label>Result: </label><input type="text" id="result" readonly>

<script>
function calculate() {
  let a = parseFloat(document.getElementById("num1").value);
  let b = parseFloat(document.getElementById("num2").value);
  let op = document.getElementById("op").value;
  let res;
  if (op === "+") res = a + b;
  else if (op === "-") res = a - b;
  else if (op === "*") res = a * b;
  else if (op === "/") res = (b === 0) ? "Error: div by 0" : a / b;
  document.getElementById("result").value = res;
}
function clearAll() {
  document.getElementById("num1").value = "";
  document.getElementById("num2").value = "";
  document.getElementById("result").value = "";
}
</script>
Output
Example: Number1=8, Number2=2, Operation=Division (/), click Calculate → Result box shows: 4 If Number2=0 and Division is chosen → Result box shows: "Error: div by 0" (caught before an actual crash) Clicking Clear empties all three fields back to blank.

<!DOCTYPE html>
<html><head>
<style>
  body { font-family: Arial; background: #f2f2f2; }
  .form-box { width: 320px; margin: 40px auto; background: white;
                padding: 20px; border-radius: 8px; box-shadow: 0 2px 6px #ccc; }
  .form-box input { width: 100%; padding: 8px; margin: 6px 0 2px;
                       border: 1px solid #ccc; border-radius: 4px; }
  .error { color: red; font-size: 12px; min-height: 14px; }
  button { width: 100%; padding: 10px; background: #2e7d32; color: white;
             border: none; border-radius: 4px; margin-top: 10px; }
</style>
</head><body>

<div class="form-box">
  <h2>Register</h2>
  <form onsubmit="return validateForm()">
    <label>Name</label>
    <input type="text" id="name">
    <div class="error" id="nameErr"></div>

    <label>Email</label>
    <input type="text" id="email">
    <div class="error" id="emailErr"></div>

    <label>Password</label>
    <input type="password" id="pass">
    <div class="error" id="passErr"></div>

    <label>Mobile Number</label>
    <input type="text" id="mobile">
    <div class="error" id="mobileErr"></div>

    <button type="submit">Register</button>
  </form>
</div>

<script>
function validateForm() {
  let ok = true;
  let name = document.getElementById("name").value.trim();
  let email = document.getElementById("email").value.trim();
  let pass  = document.getElementById("pass").value;
  let mobile = document.getElementById("mobile").value.trim();

  // reset all error messages first
  ["nameErr","emailErr","passErr","mobileErr"].forEach(id =>
    document.getElementById(id).innerText = "");

  if (name === "") {
    document.getElementById("nameErr").innerText = "Name cannot be empty"; ok = false;
  }
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    document.getElementById("emailErr").innerText = "Enter a valid email (e.g. name@gmail.com)"; ok = false;
  }
  if (pass.length < 6) {
    document.getElementById("passErr").innerText = "Password must be at least 6 characters"; ok = false;
  }
  if (!/^\d{10}$/.test(mobile)) {
    document.getElementById("mobileErr").innerText = "Mobile number must be exactly 10 digits"; ok = false;
  }
  return ok;   // false blocks submission, true allows it
}
</script>
</body></html>
Output
Try clicking "Register" with everything blank → four red error lines appear at once: Name cannot be empty Enter a valid email (e.g. name@gmail.com) Password must be at least 6 characters Mobile number must be exactly 10 digits Fix all four (e.g. name="Aditi", email="aditi@gmail.com", password="secret1", mobile="9876543210") → all error lines clear and the form submits successfully.

3. jQuery To-Do List (add / remove / mark complete)

jQueryeventsDOM manipulationCSS

Covers: jQuery selectors, .click(), .append(), .remove(), .toggleClass() — a very common 7–9 mark "build an interactive list" style question.

<style>
  #taskInput { padding: 6px; width: 200px; }
  #taskList li { padding: 6px; border-bottom: 1px solid #ddd; cursor: pointer; }
  .done { text-decoration: line-through; color: gray; }
</style>

<input id="taskInput" placeholder="New task...">
<button id="addBtn">Add</button>
<ul id="taskList"></ul>

<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
<script>
$(function() {                                    // $(document).ready shorthand

  $("#addBtn").click(function() {
    let task = $("#taskInput").val().trim();
    if (task === "") return;
    $("#taskList").append(
      "<li>" + task + " <button class='delBtn'>✕</button></li>"
    );
    $("#taskInput").val("");
  });

  // click a task's text → toggle "done" style (event delegation, works for future items too)
  $("#taskList").on("click", "li", function(e) {
    if (!$(e.target).is("button")) {
      $(this).toggleClass("done");
    }
  });

  // click ✕ button → remove that specific <li>
  $("#taskList").on("click", ".delBtn", function() {
    $(this).parent("li").remove();
  });

});
</script>
Output
Type "Buy groceries" → click Add → a new list item appears: Buy groceries ✕ Click the task text → strikethrough style toggles on/off (marks complete/incomplete). Click the ✕ button → that task is removed from the list immediately.
Why .on("click", "li", ...) instead of .click() directly on "li": this is event delegation — items added after the page loaded (new tasks) still get the click behaviour, because the listener is actually attached to the parent list and checks which child was clicked, rather than being attached to each <li> individually at page-load time.

4. JSON "Contact Book" — form data stored & displayed via JSON

JSONarrays of objectsDOMforms

Covers: building a JSON array from repeated form submissions, looping through it, and rendering a table — directly maps to the syllabus line "handle HTML form, store data in JSON object... display using jQuery/JavaScript".

<input id="cName" placeholder="Name">
<input id="cPhone" placeholder="Phone">
<button onclick="addContact()">Save Contact</button>

<table id="contactTable" border="1">
  <tr><th>Name</th><th>Phone</th></tr>
</table>

<script>
let contacts = [];   // this array of {name, phone} objects IS our JSON structure in memory

function addContact() {
  let name  = document.getElementById("cName").value;
  let phone = document.getElementById("cPhone").value;
  if (name === "" || phone === "") { alert("Both fields required"); return; }

  contacts.push({ "name": name, "phone": phone });   // add new JSON object to array

  let jsonString = JSON.stringify(contacts);
  localStorage.setItem("contacts", jsonString);   // persist as JSON text

  renderTable();
  document.getElementById("cName").value = "";
  document.getElementById("cPhone").value = "";
}

function renderTable() {
  let table = document.getElementById("contactTable");
  table.innerHTML = "<tr><th>Name</th><th>Phone</th></tr>";   // reset, keep header
  for (let c of contacts) {                                    // loop through JSON array
    let row = table.insertRow();
    row.insertCell(0).innerHTML = c.name;
    row.insertCell(1).innerHTML = c.phone;
  }
}

// on page load, restore any previously saved JSON data
window.onload = function() {
  let saved = localStorage.getItem("contacts");
  if (saved) { contacts = JSON.parse(saved); renderTable(); }
};
</script>
Output
Enter Name="Rohan", Phone="9998887776" → click "Save Contact" → the table gains a new row: | Rohan | 9998887776 | and the same data is saved as JSON text in localStorage, e.g.: [{"name":"Rohan","phone":"9998887776"}] Refresh the page → onload reads that JSON back with JSON.parse() and the table re-appears automatically (data survives a reload).
Why this is a good exam answer template: it demonstrates the full JSON round-trip — building a JSON array (push), converting to text (stringify) to store it, and converting back (parse) to use it again — which is exactly what "explain JSON and use it to store/transport data" questions are testing.
